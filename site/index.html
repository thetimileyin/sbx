Bitcoin transaction relay checker

Will your transaction relay?

Nodes on different versions don't all accept the same transactions. sbx checks yours against Bitcoin Core 28.4 to 32.1 and Knots 29.4.3 at once, on your own machine. It shows which versions accept it, which reject it, why, and how much of the network runs each.

How it works

Real nodes, run on your machine

Runs locally, never broadcasts

Each version runs on a private regtest network on your computer. Nothing is sent to mainnet, and there are no accounts.

Official, verified binaries

sbx downloads the official releases and only uses one if its checksums are signed by at least three known builders.

Explains the split

Each reject reason is put in plain words, and the known policy difference is named when versions disagree. Shares come from the public Bitnodes snapshot.

Two limits: Bitnodes only counts nodes that accept incoming connections, and a share isn't the same as reaching a miner. That depends on how nodes connect and on what miners run.

Get started

Install, start the nodes, check

Install · macOS or Linux
curl -fsSL https://raw.githubusercontent.com/thetimileyin/sbx/main/scripts/install.sh | sh
Run
sbx fetch     # download and verify each release
sbx up        # start every version on regtest
sbx serve     # open http://127.0.0.1:8338

The installer checks the archive against the release's SHA256SUMS. sbx fetch needs gpgv (brew install gnupg or apt install gpgv). From source: go install github.com/thetimileyin/sbx/cmd/sbx@latest. Try sbx demo for 24 built-in examples.

GitHub Action

Fail CI when a version won't relay it

.github/workflows/relay.yml
- uses: thetimileyin/sbx@v0
  id: sbx

# Build transactions against the sandbox wallet, then:
- run: sbx check --file txs.txt   # exits 3 if any version rejects

The action installs a verified release, starts every version (cached between runs) and gives your code the sandbox wallet's RPC. Full example
